Interface TUI

BANG! présente une interface web TUI monochrome — terminal esthétique, thème couleur unique, fond quasi-noir.

Layout

ZoneDescription
HeaderSélecteur de thème (AMB/GRN/RED/TRQ/WHT) + version
Panneau gaucheFormulaire de génération : mode, BPM, steps, chaos, gravity, CC depth, dynamics, poly, météo
Panneau centralVoix générées — note MIDI, DNA coloré, boutons thin, tags Markov/Babka/CC
Panneau droitPianoroll SVG + contrôles de zoom
LogHistorique des exports (timestamp, fichier, seed, BPM, mode, météo)

Thèmes couleur

Le bouton de thème change la couleur d'accent de toute l'interface. Le choix est mémorisé dans localStorage.

BoutonNomCouleur accent
AMBAmberrgb(255, 170, 0) — défaut
GRNGreenrgb(0, 255, 65)
REDRedrgb(255, 34, 0)
TRQTurquoisergb(0, 220, 200)
WHTWhitergb(200, 200, 200)
L'implémentation repose sur des variables CSS RGB (--ar/--ag/--ab) permettant de composer des variantes alpha (rgba(var(--ar),var(--ag),var(--ab),0.45)) sans duplication de code.

Panneau Voix

Chaque voix affiche sur deux lignes :

  • Ligne 1 — note MIDI (éditable), nom, boutons thin (×1 / ÷2 / ÷4), tag de type
  • Ligne 2 — DNA coloré cliquable · clic → champ d'édition · Escape → annuler · Enter → valider

La modification d'un pattern met à jour le pianoroll en temps réel (via /voice/preview + debounce 350 ms) sans perdre le focus.

Pianoroll

SVG généré côté serveur. Chaque cellule affiche l'atome correspondant (x − ? ↺ ░). Les P-locks Volca Drum apparaissent sous le piano principal.

Zoom : boutons − / + → 6 niveaux : ×0.5 · ×0.75 · ×1 · ×1.5 · ×2 · ×3

API HTTP

Toutes les réponses HTMX retournent du HTML. Les endpoints JSON retournent application/json.

Génération & export

MéthodeRouteDescription
GET / Interface principale — rendu complet de index.html
POST /generate Génère de nouvelles voix + pianoroll. Retourne HTML (voix + OOB pianoroll). Paramètres form : mode, chaos, bpm, steps, gravity, cc_depth, out, temporal, vel_floor, vel_ceiling, vel_curve
POST /export Génère + écrit le fichier MIDI. Retourne une entrée de log HTML. Paramètre supplémentaire : dest_dir (dossier destination, défaut = exports/)
POST /export/song Génère une song complète en plusieurs fichiers (structure intro/couplet/climax/outro). Retourne log HTML.
POST /weather Rafraîchit la météo Scaër. Retourne HTML du widget météo.

Pattern & voix

MéthodeRouteDescription
GET /pattern Retourne JSON de l'état courant : BPM, steps, step_ms, voices[] avec events (step, velocity, prob, ratchet, atom, plocks)
POST /voice/preview Met à jour un pattern en mémoire + retourne HTML pianoroll uniquement (pas de rechargement voix → pas de perte de focus). Params : idx, pattern
POST /voice/pattern Valide un pattern modifié → met à jour voix + pianoroll (OOB swap). Params : idx, pattern
POST /voice/thin Applique un thinning sur une voix (×1/÷2/÷4). Params : name, factor. Retourne HTML voix + OOB pianoroll.
POST /notes Applique un remap de notes MIDI. Form : remap_{name}=<note 0-127> pour chaque voix. Retourne HTML voix + OOB pianoroll.
POST /poly Définit le max de voix simultanées. Param : max_poly (0 = infini). Retourne HTML pianoroll.

Syntaxe DNA

Les atomes DNA sont les briques de base. Ils s'enchaînent sans séparateur.

SymboleNomTriggerVelocityProbRatchetJitter
xHitoui105100%×1—
-Silencenon————
?Probableoui9050%×1—
↺Ratchetoui110100%×3—
░Ghostoui85100%×1±25ms

Exemples

x---x---       → kick sur 1 et 3
x-x-x-x-       → hi-hat double-croche
?-?-?-?-       → pattern 50% aléatoire
x-░-x-░-      → ghost notes sur les temps faibles
↺---x---      → ratchet sur le 1

Syntaxe Babka ⚗

Extension de DNA inspirée de Strudel/TidalCycles. Tout pattern DNA reste valide dans Babka.

OpérateurSyntaxeComportement
[ ] [a b c] Subdivision — n atomes partagent 1 step (durées divisées équitablement)
< > <a b c> Alternance — sélectionne une alternative par cycle (alternatives séparées par espaces)
( ) x(n,k) Euclidien inline — distribue n triggers sur k steps (algorithme de Bresenham)
[x(n,k)] [x(n,k)] Euclidien overlay — k steps euclidiens compressés dans 1 step

Subdivision [a b c]

[x x]            → 2 hits dans 1 step (16e → 32e)
[x x x]          → triolet dans 1 step
x-[x x]-         → hit · silence · 2 hits subdivisés · silence
[x x]-[x x x]-   → combinaison
La durée totale du groupe reste 1 step quelle que soit la profondeur d'imbrication.

Alternance <a b c>

<x- -x>                      → cycle 0: x-  |  cycle 1: -x  |  ...
<x---x--- x-[x-]x-->         → alternance de patterns complexes
<x ↺ ?>                     → alterne hit / ratchet / prob par cycle
Alternatives séparées par espaces au niveau 0. Les imbrications [] ou <> internes sont correctement gérées.

Euclidien inline x(n,k)

x(3,8)   → 3 hits sur 8 steps : x--x--x-
x(5,8)   → 5 hits sur 8 steps : x-xx-xx-
?(2,8)   → 2 hits probables sur 8 steps
↺(2,8)  → 2 ratchets sur 8 steps
Tout atome DNA supporte le suffixe euclidien. Les k steps sont générés à durée 1.0 (séquence plate).

Euclidien overlay [x(n,k)]

[x(3,4)]  → 3 hits sur 4 steps, compressés dans 1 step
[x(3,8)]  → 3 hits sur 8 steps dans 1 step (durées = 0.125 chacune)
[x(n,k)] overlay ≠ x(n,k) inline : les k steps sont normalisés pour tenir dans 1 step de base.

Combinaisons

x-[x x]-?                   → hit · silence · 2 hits · prob
<x---x--- x-[x-]x-->        → alternance avec subdivision
<[x x]- x-->                → subdivision dans alternance
↺-[x ?]-░(2,4)             → ratchet · silence · prob+hit · 2 ghosts euclidiens

BangEngine — API Python

from bang_engine import BangEngine, dark_chain
import babka

e = BangEngine(
    bpm=120,
    ticks_per_step=120,
    vel_floor=20,
    vel_ceiling=110,
    vel_curve=0.7,
)

e.add_voice(36, "x---x---")                       # DNA simple
e.add_voice(42, ["x-x-", "x--x"])                 # polyrythmie (liste)
e.add_markov_voice(dark_chain(), "x-?-")           # mélodie Markov
e.add_babka_voice(38, "x(3,8)")                    # euclidien
e.add_babka_voice(36, "<x-[x x]- [x x]-->")       # alternance + subdivision
e.add_cc_drone(control=74, breakpoints=[20,100,20])

e.export_midi(num_steps=64, filename="out.mid")
